# 前端方案设计

## 何时使用

- 用户要求“出方案”“怎么设计”“先别写代码，先分析实现方式”。
- 新增页面、复杂弹窗、多步骤流程、跨页面状态或路由变更。
- 需要判断组件复用、接口封装、权限控制、缓存策略和错误处理。
- 需求有多种实现方式，需要比较成本、风险和扩展性。

## 设计原则

- 优先复用项目已有组件、公共方法、过滤器、指令和样式。
- UI 主体系优先使用 `llsweb`，补充组件按需使用 `link-ui-web`，兜底才使用 `element-ui`。
- 页面放入对应角色 `src/views/` 目录，复用组件放 `src/components/`。
<!-- - 接口统一封装到 `src/api/`，页面层不散落请求路径和方法细节。 -->
- 新增页面、入口或跳转时同步检查 `src/routes.js`。
- 非必要不直接操作 DOM，优先 Vue 数据驱动。
- 大列表、导出、下载和批量操作必须评估分页、分批或后端聚合能力。

## 设计维度

### 页面结构

- 页面目录、路由分区、菜单入口、返回链路。
- 是否使用标准列表页、标准弹窗、详情页、步骤页或独立组件。
- 页面是否需要 keep-alive 或 `pageCache`。

### 组件拆分

- 当前页面私有逻辑放在页面内。
- 多页面复用或复杂逻辑沉淀为 `src/components/` 组件。
- 父子通信优先 `props + $emit`，复杂流程可用 `$refs.xxx.init()` 返回 Promise。

### 数据与接口

- 查询、详情、提交、导出、枚举接口分层设计。
- 列表必须分页，查询条件集中生成，避免循环请求。
- 金额计算使用 `decimal.js`，除法和比例显式指定精度和舍入策略。

### 交互与状态

- loading 类型：表格查询用局部 loading，提交、导出、弹窗内查询用全局 loading。
- 错误必须对用户可见，禁止空 `catch` 或只 `console.log`。
- 提交类操作要防重复点击、失败恢复 loading、成功后刷新数据。
- 路由参数如需加密，复用 `src/common/routerEncrypt`。

## 工作流程

1. 读取需求、相邻页面、路由和已有组件。
2. 确定页面落位、路由、入口和权限。
3. 设计组件层级、数据流、接口封装和状态缓存。
4. 识别复用能力、风险点和降级方案。
5. 输出方案、文件清单、接口清单和自测范围。
6. 方案确认后再进入实现。

## 自检清单

- [ ] 是否复用项目已有组件和公共能力。
- [ ] 是否遵守目录、路由和 API 分层规范。
- [ ] 是否覆盖 loading、错误提示、重复提交和空数据。
- [ ] 是否避免循环请求、全量查询和大数据量前端处理。
- [ ] 是否明确功能开关、灰度或回滚需求。
